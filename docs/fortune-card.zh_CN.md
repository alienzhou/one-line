# 一签：像素收藏版

本轮完成用户后续提出的 **2000 条以上完整签文阶段目标**：共 2112 条逐条创作的句子，
8 种心情 × 3 种口吻，每组 88 条。最初的一万条以上独立签文仍是后续扩充目标，
不以皮肤组合冒充已完成。三种口吻为温柔有锋芒、抽象嘴替、克制诗意；心情可选随缘。
内容源为 `assets/fortune/corpus.json`。

## 产品定位

给生活有压力的人一句可以留下、作为个人签名展示的话。选择心情，抽一封来信，
按需换外观，再留下一张签名卡。重新抽签不替换已保存的卡，确定留下才会替换。
重启直接展示保存的签名；公开展示页显示系列名与句子，不显示抽签时的压力标签。

不需要账号、联网或付费，不设每日额度、连续签到、稀有等级、凶签或保证兑现的预言。
音频和无线栈不启动。每条内容都是完整句子，运行时不组合句子片段。

### 四个原创像素系列

| 系列 | 构图 | 微动效 |
| --- | --- | --- |
| 夜航电台 | 不对称夜窗、城市、台灯、猫或收音机 | 雨移动一像素，猫偶尔眨眼 |
| 旷野来信 | 层叠山景、小屋或帐篷、草地与溪流 | 缓慢的云、炊烟、偶尔的萤火 |
| 宇宙邮局 | 齿孔邮票、抖色星球、星环与信封 | 少量星星闪烁 |
| 口袋花园 | 植物标本边框、盆栽、杯子或猫 | 蒸汽、偶尔的光点或眨眼 |

画布为 **108 × 58 RGB565**，关闭抗锯齿，整数放大 2 倍。插画位于 240 × 320 屏幕的
(12,38)–(227,153)。正文使用独立的 20 px 中文字，辅助标签为 12 px，文字不随动画移动。
按实际字宽显式换行，优先保留短分句，避免中文收尾标点出现在行首，原文字节不变。

视觉编号对应 4 系列 × 6 色调 × 1024 个程序种子，共 **24576** 个画面。
种子改变场景细节和像素簇。纯画布与 LVGL 实渲染均遍历 24576 个编号，
不含签文和编号的插画区域像素哈希全部不同。这不代表每个细节变化在人眼看来
都是全新设计；主要视觉区别由四种系列构图提供。

### 期待感与切换

抽到新内容时，先展示封好的信：轻晃、封口、翻开信封、信纸升起。十个 125 ms 步骤后，
约 **1.25 秒**揭晓整句签文与像素场景。按确定可跳过；期间其他键不会继续抽取或保存另一张卡。
抽签记录在动画前写入存储，动画帧不写 Flash；电量刷新不会提前打断拆信过程。

只换外观时，使用三步、约 **375 ms 的像素横向展开**，原句不动。
常态微动效为 **4 fps**，闲置 45 秒屏幕变暗后停止绘制动画帧，输入后恢复。
主机测试抽样 96 个不同场景、32 个动画相位，相对基础帧最多变化 6264 像素中的 42 个，
即 0.67%。真机帧时和耗电尚未测量。

## 内容与空间

2112 条内容逐条写为完整句子，主题覆盖没电了、被消耗、想重来、比累了、心悬着、
有点孤单、想点甜和事太多。无完全重复文本，当前最长 21 字。
使用字符二元组 Jaccard ≥0.48，再检查序列相似度 >0.72 的近似表达筛查，未发现命中对。
它检查接近的措辞，不能识别所有重复语义；口吻和情绪主题有意保持一致，
最终的语气偏好与感知重复仍需读者评价。

`python3 tools/pack_fortunes.py --release` 执行源文件明确写出的 `production_minimum`，
目前为 2001。主机测试同时要求 2000 条以上，并通过 C 解码器逐字节对照全部原文。
`long_term_target` 记录 10001；修改元数据不会产生缺少的内容。

| 资源 | 实测占用 |
| --- | ---: |
| 含结束符的原始 UTF-8 文本 | 86490 字节 |
| 11 位字符编码流 | 38674 字节 |
| 字符字典 | 3116 字节 |
| 索引与元信息 | 16896 字节 |
| 完整编码签库 | **58686 字节 / 57.3 KiB** |
| 像素画布，内部 RAM | **12528 字节** |
| 含已读位图及 CRC 的 NVS 序列化状态 | **312 字节** |

解码器只将一条签文解码到 128 字节缓冲区，不拼句、不把整个签库载入 RAM。
实现上限为 16384 条。用 `lv_font_conv 1.5.3` 从 Noto Sans CJK SC Regular
生成 12/20 px、4 bpp 子集，**每个字号覆盖 1661 个可打印字符**。
原始 OTF 仅为开发素材，不嵌入固件。许可证、来源哈希和重建方法见 `assets/README.zh_CN.md`。

## 固件与按键

工作树位于 `codex/fortune-sign` 分支，基于上游 `0b9e4c8`，原项目无关修改均保留。
BSP 原样复用，不链接 demo 页面。目标仍为 ESP32-C3、8 MB Flash、无 PSRAM、
ESP-IDF 5.5.3、LVGL 9.5.0，使用最小 NVS/PHY/factory 分区。

| 页面 | 上键 | 下键 | 确定 | 长按 |
| --- | --- | --- | --- | --- |
| 选择心情 | 上一心情 | 下一心情 | 抽签 | 下换口吻；确定看已存签名；仅组内抽尽后，上键可洗牌 |
| 拆信中 | 忽略 | 忽略 | 跳过动效 | 确定也跳过 |
| 抽签结果 | 再抽，旧签名保留 | 换外观 | 留作签名 | 确定回心情页 |
| 已存签名 | 再抽，旧签名保留 | 修改已存签名外观 | 回心情页 | 确定回心情页 |

仿射排列与持久化已读位图保证跨筛选不重复抽到签文；抽尽后需要明确洗牌。
外观使用独立排列，不受签文洗牌影响。抽签用于娱乐，不宣称密码学随机性。
参见 [ESP-IDF RNG 条件](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/random.html)。

按键回调只入有界队列，worker 持有应用状态并执行 NVS 写入，非 LVGL 任务的 UI 访问
均持有 BSP 锁。LVGL 定时器只处理画面，并在页面删除时释放。揭晓前先保存抽签历史。
存储失败明确提示可能丢失，不通过擦 NVS 恢复错误。状态采用显式编码和校验。
签库指纹变化目前会重置已读记录和签名；未来承诺内容升级保留签名之前，需要稳定编号迁移。

输入后亮度 75%，闲置 45 秒变为 15%，120 秒熄屏。熄屏后第一次事件只唤醒，不换签。
这是显示电源管理，不是深睡眠。存储 API 参见 [ESP-IDF NVS](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/storage/nvs_flash.html)，
物理断电恢复仍需真机测试。

## 验证与交付

切换筛选、全部原文解码、损坏存档拒绝、存储往返及像素渲染器测试。

最大长度、错误提示、实际控件字体和缺字负例、定时拆信、跳过和动画暂停。
